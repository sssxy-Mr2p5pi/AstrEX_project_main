### 2.2 移动参考

令 `x_start` 为第一条有效状态的位置，`target` 为最终目标。使用五次平滑曲线：

```text
s = clip((t_sim - t_start) / T, 0, 1)
x_ref = x_start + (target - x_start) * (10*s^3 - 15*s^4 + 6*s^5)
T = max(2.0, 1.875 * abs(target - x_start) / 0.05)
e = [x - x_ref, x_dot, theta, theta_dot]
F_cmd = clip(-K @ e, -5, 5)
```

上述 T 对应参考最大速度不超过 0.05 m/s。0.3 m 和 0.5 m 的参考时长分别为 11.25 秒和 18.75 秒。这是参考曲线设定，不是物理恢复成绩。

参考只按有效仿真时间推进。重复时间戳不推进。时间倒退触发故障。参考到达终点后固定，不再累加位置。目标等于起点时直接使用固定参考。

### 2.3 分开处理控制边界与成功条件

| 项目 | MoveCart | BalanceHold |
| --- | --- | --- |
| 控制位置误差 | `x - x_ref` | `x - hold_position` |
| 成功位置误差 | `x - target` | `x - hold_position` |
| 连续合格时间 | 参考到达 target 后连续 1 秒 | 连续 3 秒 |
| 四项容差 | 0.05 m、0.10 m/s、2°、0.20 rad/s | 相同 |
| 位置退出条件 | `abs(x-x_ref)>0.25 m` 或越出路径走廊/场景边界 | `abs(x-hold_position)>0.25 m` 或场景越界 |
| 仿真期限 | `T + 8 秒`，含到位稳定时间 | 阶段开始后最多 10 秒 |

路径走廊为 `[min(x_start,target)-0.25, max(x_start,target)+0.25]`，再与实际轨道范围取交集。提前检查目标在轨道范围内。不能用 `abs(x-target)>0.25` 判断移动阶段故障。

两种任务共同保留：5 N 限力、10° 杆角退出、0.5 仿真秒连续限幅退出、0.2 本地秒状态失效和 0.05 仿真秒稳定计时断点。

主动控制开始后，本地执行期限设为 `max(60 秒, 3 * 计划总仿真时长)`。GUI 等待观看和启动预热使用独立计时，不占控制期限。局部状态失效阈值仍为 0.2 秒。

C 阶段的“初角减半”和“5 cm 初位误差缩小至 2.5 cm”属于历史恢复实验判据。不要把它们套到移动后保持的新状态，否则接近零的小初角会产生不必要的严苛条件。正式两阶段演示使用固定四项容差，保留历史 C 记录原样。

## 3. 4B：收紧 dry-run 验收

### 3.1 执行方式

完成必要代码检查后，只启动一次 Isaac 只读会话。使用零力、近直立状态，分别计算 0 → +0.3 m、0 → −0.3 m、0 → +0.5 m 的移动参考。

补充一组很小的消息序列检查，覆盖新参考与顺序切换。消息序列可以直接构造，不积分动力学，不建立另一套仿真器。所有消息注入只在测试进程内部进行，不向真实 `/joint_states` 发布伪造反馈。

可以读取现有 C trace 中少量有效状态作为计算输入。历史轨迹只用于检查字段和计算一致性，不能作为 MoveCart 闭环通过证据。

### 3.2 必须全部满足的条件

| 验收项 | 通过条件 |
| --- | --- |
| 无施力输出 | dry-run 进程从不创建 `/joint_command` 或 raw command publisher。唯一 Isaac 的 Controller 输入保持零 |
| 同一计算链 | dry-run 与实控共用函数。输出 `x_ref`、四状态、`F_raw`、`F_cmd` 和阶段状态 |
| 参考正确 | 起点等于真实起点，方向正确，参考不越过 target，终点固定，最大参考速度不超过配置 |
| 时间正确 | 参考按仿真时间推进。重复时间不推进。倒退、断流和状态间隔按既定规则处理 |
| 力正确 | 用保存的 K 和输入独立核对 `-K@e`。限幅后始终在 ±5 N，pole torque 始终为零 |
| 状态正确 | 四状态来自同一有效消息，关节换序仍正确，无效消息不变成可执行控制输入 |
| 成功不提前 | 参考未到终点，即使暂时处于目标容差内，也不能报告移动成功 |
| 连续时间正确 | 条件中断重新计时。重复缓存不累计。Move 与 Hold 分别使用 1 秒和 3 秒 |
| 故障优先 | 同一时刻满足成功和故障条件时，以故障结束 |
| 切换正确 | Move 成功时间戳、新到达状态 S1、Hold 启动严格有序 |

为了缩小测试量，将相邻边界放进同一组参数化测试。已有 C 测试已覆盖的行为只运行相关回归，不另写同义测试。

零力 dry-run 的滑车不会追随参考。因此，不把位置跟踪偏差或持续建议力饱和判成物理恢复失败。保留这些诊断量，但将需要真实施力响应的越界/饱和评价留给实控。不得为了 dry-run 通过而关闭真实模式的保护。

dry-run 输出 `DRY_RUN_PASS`，不输出物理任务 `SUCCESS`。任一接线或计算条件失败，先修正该项，再进入实控。通过后提交一次 Git commit。

**[人工 H1：首次 GUI 观看准备]** 你在桌面确认窗口可见，镜头同时包含滑车、摆杆和预计移动范围。可以拖动相机调整视角。回复一次“GUI 已就绪，可以开始”，后续三组按顺序自动执行。若窗口或相机已经可由现有工具确认，无须再增加这一等待。

| 工况 | 初位 → 目标 | 初角 | 验收目的 |
| --- | --- | --- | --- |
| M1 | 0 → +0.3 m | 0° | 首次移动、减速与在线到位判定 |

### 4.3 M3 的最小顺序流程

```text
真实状态 S0
→ MoveCart 平滑移动至 +0.5 m
→ 最终目标四项容差连续满足 1 秒
→ 保存 t_move_success，停止 MoveCart 更新
→ 发布零命令
→ 接收本次零命令之后新到达且 stamp > t_move_success 的有效状态 S1
→ 以固定 +0.5 m 为目标启动 BalanceHold
→ 四项容差连续满足 3 秒
→ 停止控制、发送最终零命令
→ 核对 Controller 清零，报告 DEMO_SUCCESS
```

两阶段共用同一进程和发布器，阶段内部只有一个控制任务。等待 S1 期间不重置仿真、不偷偷继续 MoveCart，也不调用当前节点会销毁资源的整段 `finish()`。

S1 等待上限为 0.5 本地秒。缓存必须仍满足 0.2 秒新鲜度。若等待超时、发生故障或初态越界，演示失败。新阶段单独初始化稳定计时，不能继承 MoveCart 的 1 秒。

阶段切换仅发送必要的零命令，不在两个阶段之间插入耗时的完整进程清理。任务整体结束时才执行已有多次清零和资源释放。保存零命令发布时间及 Controller 响应，不声称零命令必然被每一帧观察到。

正式成功以四状态和时间戳为准。GUI 只确认演示确实可见。为方便观看，运行结束可保留窗口，但不继续隐藏施力。清零后摆杆不保证一直直立，不把成功后的自由运动改判为控制阶段失败。

**[人工 H2：最终视觉确认]** M3 结束后，你确认看到滑车移动至目标附近、摆杆恢复并保持。无需人工计算容差。执行器根据原始日志给出物理结论。无需默认录屏。

### 4.4 出现失败时的最短处理

先区分实现错误、GUI 导致的反馈延迟和控制能力不足。前两者修正后只重跑受影响工况。

若移动引起持续限幅或跟踪偏差，先把参考速度从 0.05 降到 0.03 m/s。对应移动期限随 T 调整。保持 K、5 N 限力和成功容差不变。只做一次有依据的速度修正，不开展参数搜索。

若 0.03 m/s 仍失败，记录具体原因，再决定是否需要改 K。此时不宣称已完成 Step 4，也不无限重复同一工况。

若改动 K 或公共控制逻辑，补一个 C 代表工况回归。若只改运行器、相机或报告，不重跑 C 矩阵。

每段完成就提交，不自动 push。只提交该段改动，保留用户原有暂存内容。必要时使用独立索引，避免将 AstrBotEX、接口包和 tmp 包改动混入提交。

P4 只删除已经没有依赖的入口，不再改变控制行为。完成后检查 import、`--help`、console entry 和相关单元测试。没有行为变化就不重复三个 GUI 工况。若清理改变了执行路径，则只补受影响的最小运行检查。

本轮编写计划不执行上述提交或清理。后续执行计划时，列明范围内的常规修改、仿真和清理不再逐项请求确认。
