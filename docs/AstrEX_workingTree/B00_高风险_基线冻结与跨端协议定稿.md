## 2. 必须定稿的消息

### 2.1 传输

沿用 `astrbotex-zmq/version=1` 外层封包、request id与reply_to。新增业务payload带 `schema_version=1`；旧端不认识新method必须报unsupported，不能退回旧proposal偷偷执行。

| method | 方向 | 行为 |
|---|---|---|
| `decision.context.get` | AEB→EX | 目录、说明、观测、执行状态；只读 |
| `decision.goal.submit` | AEB→EX | 原子提交goal+参数，支持expected_revision |
| `decision.goal.cancel` | AEB→EX | 取消当前goal；应答受理不代表已经停止 |
| `decision.goal.renew` | AEB→EX | 当前控制权/goal租约续期；不得创建新goal |
| `decision.state.get` | AEB→EX | 活动goal、待替代goal、执行状态、ex_session |
| `decision.events.get` | AEB→EX | 按event_seq恢复反馈；历史裁剪返回resync_required |
| `decision.feedback` | EX→AEB | 反馈通知；AEB确认已持久接收的event_seq |

身份取自已配置且受信的连接映射，不相信payload自称管理员。request_id幂等；同ID不同payload报冲突。传输ACK、提交受理、goal active、动作完成是四个不同事实。

### 2.2 GoalSubmit 例子

```json
{
  "schema_version": 1,
  "request_id": "req-17",
  "ex_session": "ex-boot-a",
  "task_id": "task-4",
  "step_id": "step-2",
  "goal_id": "goal-9",
  "expected_revision": 8,
  "goal_text_en": "Pick the selected cup using the arm. Keep the base stopped.",
  "allowed_actions": ["new_arm.pick_selected.v1", "new_yolo.detect.start.v1"],
  "parameters": {
    "new_arm.pick_selected.v1": {
      "target": {"observation_id": "obs-40", "stream_id": "front", "frame_id": 40, "object_id": "track-8", "selected": true}
    }
  },
  "completion": {"required_success_actions": ["new_arm.pick_selected.v1"]},
  "lease_ms": 10000
}
```

例子不意味着2D目标可直接抓取；插件必须核验深度/标定/位姿。系统安全stop/cancel始终可用，不受LLM allowed_actions遗漏限制。lease数值仅模拟配置例子，真实设备另行审定。

返回至少含 `ok, request_id, ex_session, goal_id, revision, phase`；phase为 `accepted/pending_cancel/active/blocked/rejected`。只有active进入决策。

ID由AEB/EX代码生成，LLM选内容不负责造会话、owner权限或递增revision。单台EX只接一个已获控制权的task；抢占必须带受权的显式操作。

### 2.3 命令与结果

```json
{
  "command_id": "cmd-21",
  "ex_session": "ex-boot-a",
  "goal_id": "goal-9",
  "goal_revision": 9,
  "decision_id": "dec-12",
  "owner": "new_arm",
  "plugin_generation": 3,
  "action_id": "new_arm.pick_selected.v1",
  "operation": "start",
  "params": {"target": {"observation_id": "obs-40", "object_id": "track-8", "selected": true}},
  "lease_ms": 1000
}
```

命令实例在EX内补单调接收时刻/截止时刻、环境代次和资源令牌。`command_id`不是action_id：同一动作可在不同goal执行，但同一命令不能重复开始。

动作状态：`admitted → accepted → running → succeeded/failed/canceled/timed_out/unknown`；admission也可rejected。进度可重复合并；终态互斥、不可倒退。`canceled`必须有插件停止证据；停止超时不能伪造canceled。

事件含 `event_id, event_seq, ex_session, task_id, goal_id, goal_revision, command_id, owner, status, reason_code, details`。owner由PluginContext绑定；时间由EX记录。详细业务证据可为插件自定义JSON，禁止只用自由文本决定程序状态。

### 2.4 动作声明 v2

```json
{
  "action_api_version": 2,
  "actions": [{
    "action_id": "new_base.forward.v1",
    "description": "Move forward using the bounded local controller. Stop when its lease expires.",
    "schema": {"type": "object", "properties": {"profile": {"type": "string", "enum": ["slow"]}}, "required": ["profile"], "additionalProperties": false},
    "resources": ["base_motion"],
    "operations": ["start", "cancel"],
    "requires_runtime_state": ["running"],
    "requires_observations": ["front_clearance"],
    "max_duration_ms": 1000,
    "cancel_timeout_ms": 300,
    "danger": "high"
  }],
  "observation_guide": "output_description.md"
}
```

字段与示例由B00冻结，后续不得自行拼不同版本。资源名是控制器实际互斥关系，不由LLM自由生成。v2不需要command topic；旧topic动作只在legacy模式存在。原 `provides` 与ROS `ports` 保留；纯动作插件由本批明确登记到运行时的哪一类槽，不借用旧motion接口伪装可执行。

`requires_observations` 名称必须能在manifest内映射到准确topic/来源；实际年龄、字段完整性由插件/框架程序检验。**不要求把各感知payload字段统一命名。**

## 3. 决策与前端契约

- 后端输入：snapshot_id、版本集合、英文goal、绑定参数摘要、相关观测原JSON与说明、各owner状态及候选项。
- 输出：每owner的option_id、可选confidence/分布/后端model、耗时。不能输出新的goal、任意handler、任意参数、任意topic。
- 一期候选动作数超后端能力时明确报错或按预审分组；禁止静默截断导致stop/wait消失。
- `keep`是保持既有动作，不是重发start；`request_replan`是报告无法继续，不是模型自己改goal。
- 固定页面API草案见B08；B09开工前必须生成稳定样例与契约测试。
