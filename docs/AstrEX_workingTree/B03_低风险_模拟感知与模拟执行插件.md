# B03｜低风险｜模拟感知与模拟执行插件

作用：建立不依赖ROS、硬件或云模型的确定性闭环，供后续批次调试。预计2–3人日。依赖B01/B02，SDK未冻结不得开工。

## 1. 白名单

新增 EX `examples/decision_sim/`、`tests/fixtures/decision/`、`tests/test_decision_sim_plugins.py`；需要部署时复制到全新的测试data目录。不得改核心SDK、真实ROS绑定、真实硬件配置；不得启用废弃插件。

三个示例owner：`sim_perception`、`sim_base`、`sim_arm`。不连接摄像头、不发CAN/ROS控制、不调用Jev。

## 2. 步骤及本步验收

| 步骤 | 工作 | 本步验收 |
|---|---|---|
| 1 | 用B02 manifest声明动作与说明路径，默认禁用 | Catalog显示正确owner/动作；无真实端口 |
| 2 | 感知按B01脚本发布原JSON，支持正常/空/过期/失效 | 序号、来源、时效可被测试控制 |
| 3 | 底盘模拟 forward/left/stop；机械臂模拟pick | 有accepted、running、success，完全无物理副作用 |
| 4 | 支持配置指定失败、拒绝、延迟、目标丢失 | reason_code稳定，不能随机碰运气 |
| 5 | 用虚拟时钟推进租约和完成，不靠长sleep | 单测试可重现；重复运行结果一致 |
| 6 | 实现取消和超时状态，记录每个start次数 | cancel有确认；重复command不重复执行 |
| 7 | 写“拿杯子”三步场景与“中途换目标”场景 | 所有动作与goal关联可追溯 |

## 3. 测试及通过标准

测试至少覆盖：正常闭环、受理后失败、受理前拒绝、执行中取消、lease到期、旧command重发、缺参数、旧目标、goal替代、两个owner并发但资源互斥。

通过：至少10场景×20次，事件序列与期望相同；真实网络/设备调用计数=0；所有动作只通过B02接口；全程无TopicBus控制命令。墙钟性能不作为虚拟时钟测试的证据。

弱agent只按场景修模拟器；如果SDK缺方法、状态定义矛盾，报告给B02，不修改框架“让测试过”。

## 4. 交接与回滚

交付manifest、小说明、场景清单、可重复回放命令。回滚禁用并卸载测试data中的模拟插件即可；不接触用户的现有plugins目录。
