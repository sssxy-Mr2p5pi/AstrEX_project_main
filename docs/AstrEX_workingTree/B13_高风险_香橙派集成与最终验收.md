# B13｜高风险｜香橙派集成与最终验收

作用：验证arm64/ROS2环境中的下一代整体闭环，进行故障/恢复演练与最终分级签字。预计3–5人日。依赖B12。

## 1. 设备信息与授权边界

现有仓库 `docs/ROS2-ACCEPTANCE.md` 记录香橙派为Ubuntu22.04/arm64/Python3.10/ROS2 Humble/CycloneDDS，EX Dashboard8765，曾使用Domain73完成无实物测试。**这些是历史记录，本次未连接设备复核，不得当当前在线事实。**

执行前向设备负责人确认：SSH/部署权限、当前运行任务、可用端口、ROS Domain/Topic、是否允许停现有EX、是否连接真实执行器、急停方式。文档授权不等于现在可覆盖生产部署。

先用并行验收实例和独立data/Domain/Topic；不修改现有AstrBot/NapCat容器，不默认占用原8765。内存不足无法并行时，先批准维护窗口与回滚方案。

## 2. 两级设备验收

- **HIL-通信级**：香橙派EX与另一进程/容器的ROS模拟控制节点交互，验证真实DDS与业务ACK；不驱动物理设备。
- **实物级**：只有设备、驱动、标定、急停和人工授权齐全后开展。若只提供香橙派而无机械臂/底盘，相应项标NOT_RUN，不影响框架级报告，但阻止实物级签字。

远程Windows到香橙派的DDS多播不作默认前提；先验证同一Linux宿主机或明确配置的ROS网络。不要假设Tailscale自动转发DDS发现。

## 4. 故障注入要求

至少覆盖：Jev网络不可用、LLM provider不可用、AEB退出、EX退出、感知断流、插件worker阻塞、执行端不ACK、DDS节点重启、模型配置切换、ROS切normal失败、磁盘/账本写入失败。

断网可先用测试代理/假服务定向注入，禁止断整台设备网络影响其他服务。进程终止只针对独立验收实例。每次注入都观察：新动作gate、当前动作实际状态、远端watchdog、反馈恢复、页面告警。

## 5. 数量与通过门槛

- 完整目标平台测试无未解释FAIL；必须执行的ROS/安全场景不可skip。
- goal替代100次、环境切换20次；旧命令生效=0、重复start=0、资源泄漏=0。
- 运行至少2小时混合模拟负载；队列容量不越界、无未回收活动命令、无持续内存/线程增长。模型付费测试可抽样，不要求全程云轮询。
- 正常任务成功率与B07冻结指标一致；报告任务级失败、参数绑定失败和模型选择错误，不只算API200。
- APIkey/内部JSON泄露=0，跨会话控制=0；任一出现立即停止验收。
- ROS模拟停车时限按B11；实物停车必须给真实控制器日志/传感器证据，不以EX发stop的时间冒充。
- 执行模式开启需设备/场景评测通过；未通过时维持shadow或disabled，不能“先上线观察”。

## 6. 发布与回滚

发布前：备份配置（不含secret）、保存镜像digest、记录数据schema、确认无活动动作；设disabled并在维护窗口切换。数据库若有不可逆迁移，不能仅回退镜像，需经过验证的数据迁移/恢复方案。

回滚：关闭新动作gate→确认远端停机→停止验收/新实例→恢复批准的配置与镜像→保持runtime stopped、决策disabled→重新同步任务状态。回滚不复活废弃插件，也不自动执行旧goal。

演练验收后默认恢复安全状态：无活动task/goal、runtime stopped、决策disabled、测试控制绑定禁用；实际生产启用需另有明确授权。
