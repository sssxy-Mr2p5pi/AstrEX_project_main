# B02 协调与验收补充

本文件是协调端对 B02 原计划的实现约束和审查清单，不代表功能已实现或测试已通过。最终协议以审阅后的 `docs/DECISION-CONTRACT.md` 为准。

## 范围与默认行为

- 本轮实现 B00、B01、B02；不实现 B03–B13，不调用云模型或真实硬件，不中断生产服务。
- `control_mode=legacy` 为默认。新 Dispatcher 的执行 gate 默认关闭；独立测试可显式启用 decision 模式。
- decision 模式必须同时隔离 legacy proposal 和旧 policy/skill/motion 输出，避免两条路径同时控制设备。只隐藏 UI 按钮不算隔离。
- 切回 legacy 前必须核对停止与资源占用，不得自动恢复旧运动。

## 授权与下发顺序

动作命令先按 B00 验证，再使用框架持有的当前 session、goal/revision、allowed_actions、绑定参数、插件 generation、环境 generation 和 catalog/config 版本核验。不得从命令 payload 的自报信息推导授权。

在任何插件副作用之前，原子记录 command_id、完整规范化 payload 和资源占用并提交。相同 ID/相同 payload 查询原状态；不同 payload 冲突。崩溃恢复只恢复记录，绝不重新下发命令。

执行前再次检查 gate、generation、deadline 和观测年龄。观测的 `age_ms` 是快照值，不能在排队后直接当作当前年龄。`received_monotonic_ns` 必须来自框架；业务字段和目标选择不能修改原始感知数据。

## Actor 与停止

- 动作走独立有界普通队列，按条数与字节限制；不复用无界 cast 邮箱，不覆盖已接收条目。
- 取消走独立有界优先通道。停止优先只能抢占尚未执行的调用，不能终止卡住的 Python handler；满队列必须可见失败并关闭新 start。
- handler 只做有限验证和本地状态准备，模拟验收预算 20ms；物理推进在 worker 或受控独立执行器中完成。
- 原 actor 的 `on_worker_step` 受 runtime_active/enabled 限制。动作停止中的实例必须能继续推进停止及上报，不能因 runtime.stop 或 disable 把停止过程饿死。
- unregister 不能先从 registry 删除实例再尝试停车。停止不确定时保留可见 blocked 状态、资源占用和对旧实例的停止处理能力；新 generation 不得接收旧命令或旧报告。
- runtime.stop、fault、pause、禁用/卸载、配置重载、环境切换均须先撤销动作 gate。环境切换复用已有 ROS quiesce 生命周期，不另起 ROS context。

## Ledger 与持久化

- SQLite 写入由独立、有界 writer 负责；不能在 runtime 主锁中等待磁盘、云请求或物理停止。
- 只有已提交事件可出现在反馈/恢复查询中。状态、event_seq 和 outbox 应在同一事务内保持一致。
- 持久队列满、磁盘失败、handler 超时均为可见故障；不静默丢终态，不继续新 start。
- SDK report 的 owner/generation 由 PluginContext 绑定；插件调用者不能通过参数代报其他 owner。
- 重启时未终结记录变为 unknown/resume_review，不重放副作用；资源保持阻塞，直到显式核对停止。
- canceled 需要结构化肯定停止证据；timed_out/unknown 不代表已经停止。不能仅凭 DDS publish 成功、传输 ACK、handler 已返回或自由文本释放不确定的物理资源。
- 未知停止状态不能因 runtime 最后回到 IDLE 而消失。独立动作状态必须继续暴露 blocked/unknown。

## Catalog 与说明文件

v2 插件使用明确 `action_owner` 能力/运行槽；不要求伪装旧 motion 接口。保留既有 provides/ROS ports，v1 topic 动作只在 legacy 中可执行。

Catalog 按 owner/generation 收集同一版本的动作、配置和说明；安装、卸载、启用、禁用、配置/说明变化更新 revision。禁用项不进入可执行候选。

说明读取先拒绝绝对路径、跨平台 drive/UNC 路径及 `..`，resolve 后必须仍在插件根内；符号链接逃逸拒绝。读取最多 8KiB 加一个溢出检测字节，严格 UTF-8/纯文本，缺失显示 unavailable。不得完整读取巨大文件后才检查长度。

## 必测边界

B02 原计划 A01–A12 全部必跑、不得 skip，并补充：

1. 验证普通队列 N+1 明确拒绝且前 N 条不丢；排队过期的命令不得进入业务 handler。
2. 在 handler 真正阻塞时测试取消、上层 unknown 和独立模拟控制器 watchdog，保证释放测试阻塞并回收线程。模拟停车不宣称真实物理停车。
3. runtime 已停、owner 禁用或卸载处理中，停止状态仍能推进；未知资源不能被新 owner/generation 抢用。
4. 在 admission 提交前、提交后/下发前、运行后/终态提交前等边界使用隔离子进程崩溃测试；重启业务 start 计数不得增加。
5. 1000 条随机状态序列验证无串发、无重复 start、终态不倒退、未知停止资源不释放。
6. 不通过 TopicBus 传递动作结果；洪水和慢订阅者不得阻塞独立安全 gate。
7. 新 dispatcher、SDK 与目录测试通过后，再跑完整 EX 回归及隔离 ROS2 验证；旧环境限定跳过与新增必测项目分别统计。

每次交付应包含实际文件差异、原始测试输出和未解决问题；协调端完成最终代码审查后才在进度报告中标记验收。
